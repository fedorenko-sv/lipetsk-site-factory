# Шесть самостоятельных профилей показа

Фабрика и выбранное демо используют одну production-сборку. Профиль задаётся во время запуска сервера. В локальном preview каждый профиль получает отдельные origin, test-БД, секреты в памяти и recording-назначения.

## Команды

Сначала установить зависимости, запустить test PostgreSQL и собрать проект:

~~~powershell
npm ci
npm run db:test:up
npm run build
~~~

В нужном терминале запустить один профиль и оставить процесс работающим:

~~~powershell
npm run preview:demo -- beauty
~~~

| Профиль | Вход на своём origin | Утверждённый API scope |
| --- | --- | --- |
| auto | http://127.0.0.1:3041/ | auto,detailing |
| beauty | http://127.0.0.1:3042/ | beauty |
| medical | http://127.0.0.1:3043/ | medical |
| sports | http://127.0.0.1:3044/ | sports |
| stay | http://127.0.0.1:3045/ | stay |
| estimate | http://127.0.0.1:3046/ | estimate |

Таблица — адреса после запуска соответствующей команды. Запуск всех шести процессов необязателен: для показа достаточно нужного профиля. Фабрика запускается прежней командой npm run preview:portfolio на 3035 и сохраняет общую коллекцию.

Список и другой свободный порт:

~~~powershell
npm run preview:demo -- --list
npm run preview:demo -- stay --port 3145
~~~

Остановка — Ctrl+C в терминале этого запуска. Launcher завершает только собственный дочерний Next-процесс. Он отказывается занимать уже используемый порт.

## Поведение

- / перенаправляет на главную выбранного демо внутри того же origin. Query сохраняется.
- Собственные каталог, карточки, информация, форма и политика доступны как прежде.
- Чужие демо получают 404, включая запросы RSC/prefetch и encoded-имена. Auto сохраняет связанный подробный OBLIK.
- API проверяет точное соответствие allowlist профилю и обычные Origin/схему/версию/согласие. Несоответствие конфигурации даёт штатный 503 DEMO_NOT_READY. Валидная чужая заявка получает 404 SITE_NOT_FOUND.
- Ошибочное непустое имя DEMO_SITE_KEY закрывает страницы кодом 503 с noindex/no-store.
- При пустом/отсутствующем DEMO_SITE_KEY работает исходная фабрика. Публичные ассеты и общий код остаются частью одного build.

Шесть профилей предназначены для демонстрационных сайтов. Модель авторизованных арендаторов/кабинетов сюда не добавляется. Три шага Booking A, формула B, idempotency и outbox остаются общими.

## Тестовые данные и storage

Использовать только +70000000000. В Medical вводят организационный запрос, в Stay выбирают время обратной связи. Реальные записи, ночи, оплаты и сообщения не оформляются.

Default-БД выбранного локального профиля: lsf_test_demo_<key>_<port>. Launcher берёт проверенный TEST_DATABASE_URL или публичный локальный fixture compose (127.0.0.1:55543, lsf_test_backend), создаёт собственную test-БД и применяет существующие миграции. Guard разрешает только loopback, PostgreSQL и lsf_test_ и проверяет эффективный target до SQL.

Локальный compose хранит данные в tmpfs. Остановка приложения сохраняет БД до перезапуска контейнера; долговременное удалённое хранилище — отдельный этап запуска.

Состояние процесса: work/demos/preview-<port>-state.json; лог приложения рядом. В state находятся только PID, URL, профиль, имя БД и время. DSN/HMAC/token туда не записываются. Фабричный state и имя БД остаются в прежнем формате work/detailing/ и lsf_test_detailing_preview_<port>.

## Проверка

~~~powershell
npm run test:backend
npm run test:ui
npm run test:demo-profiles
~~~

Последняя команда использует один уже собранный build, поднимает профили последовательно на временных loopback-портах и создаёт уникальные test-БД. Для каждого проверяет собственные страницы, чужие URL/API, Origin, реальный UI → API → PostgreSQL → outbox → recording и idempotent replay. После остановки процессов удаляет только новые БД, принадлежность которым подтверждена этим прогоном. Дополнительно проверяет ошибочный режим и неверный scope на настоящем Next.

Регрессия фабрики при её работающем preview:

~~~powershell
npm run verify:demo-routes
npm run test:portfolio:system
~~~

## Следующий запуск у заказчика

Готовый профиль задаёт имя сайта и точный scope. Для отдельного хостинга нужны выбранный домен/origin, долговременная БД, постоянные приватные секреты, согласованные данные/политики и назначение администратора. Публикация и настоящие каналы выполняются по отдельному поручению. Этот пакет готовит раздельный локальный запуск и не объявляет публичные адреса созданными.

  FACT --> DBF[(Test-БД фабрики)]
  ONE --> DB1[(Своя test-БД)]
  OTHER --> DBS[(Свои test-БД)]
  DBF --> REC[Общий код recording]
  DB1 --> REC
  DBS --> REC
~~~
