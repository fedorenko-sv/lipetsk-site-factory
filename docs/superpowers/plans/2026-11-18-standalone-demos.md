# Отдельные демо для показа — продолжение разработки

Поручение владельца 18.11.2026: продолжать разработку и получить в итоге отдельные демо для показа. Общая витрина — каталог, каждое направление — самостоятельный сайт со своей навигацией и прямым входом.

## Результат пакета

Развить текущие шесть главных до связанных страниц предложения, описаний услуг/объектов, команды или условий и отдельного рабочего сценария. Сохранить независимость демо при общей кодовой базе. Не создавать шесть копий приложения и не публиковать стенды без отдельного поручения.

| Демо | Собственные разделы |
| --- | --- |
| Auto | services + 3 услуги, about, visit, booking; подробный OBLIK сохраняется. |
| Beauty | services + 2 услуги, team, studio, visit, booking. |
| Medical | directions + 2 направления, specialists, patients, information, booking. |
| Sports | programs + 3 программы, coaches, first-visit, space, booking. |
| Stay | houses + 2 дома, territory, trip, booking. |
| Estimate | windows + 2 конструкции, installation, measurement, examples, calculator. |

У каждого остаётся своя privacy. Все ссылки основной навигации, логотипа и подвала ведут внутри выбранного демо. Общая витрина открывает шесть сайтов; показ заказчику возможен по прямому адресу одного из них.

## Архитектура

Реестр страниц src/features/prototypes/pages.ts задаёт разрешённые разделы и их смысл. Редакторское содержание и составы услуг — отдельные данные. SiteConfig и Calculator config остаются единственным источником разрешённых услуг/ресурсов и цены.

Маршруты /demo/[siteKey]/[section] и /demo/[siteKey]/[section]/[itemId] проверяют оба уровня и честно возвращают 404. Статические статьи и каталоги собираются заранее. Динамические /demo/[siteKey]/booking и /demo/[siteKey]/calculator отделены от статических разделов. Они читают только разрешённый контекст услуги/ресурса/конструкции; неверный или чужой ID не выбирается молча.

Подробные карточки передают service/resource в Booking A. Для B1 выбирается допустимый product. Сервер по-прежнему независимо валидирует и сохраняет запрос; типы заявок и формулы не меняются.

## Границы

Шесть отдельных URL уже позволяют показать демо по одному; шесть публичных доменов не объявляются созданными. Для отдельного развёртывания каждый siteKey получает собственные allowlist/origin/БД и выбранный канал администратора. Настоящие документы, отзывы, контакты, расписание, свободные ночи и платежи не создаются из вымышленных данных.
