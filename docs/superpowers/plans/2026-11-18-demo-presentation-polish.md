# Показ демо: мобильная загрузка и фотосерии Stay

**Продолжение:** шесть самостоятельных демо, ветка codex/six-prototypes, PR #5.
**BASE:** 59df27630b787224b1471f18bf3b235ef8759b54.
**Цель:** закрыть измеримую часть мобильной производительности и сделать два дома Stay визуально различимыми, сохранив 69 страниц, Booking A, Calculator B1 и demo-only.

## Решения и границы

- Использовать существующий изолированный worktree portfolio. Работу выполняет архитектор лично: дополнительное делегирование не поручено владельцем.
- Локальные материалы — work/portfolio/presentation-polish; итоговые свидетельства — docs/reports/presentation-polish. Helper task-start зависит от отсутствующего соседнего subagent-driven-development/scripts; его журнал ведётся вручную, это не блокирует реализацию.
- Публичное развёртывание, настоящие каналы, цены/наличие объектов и новый Core C не входят.
- Измерения — лабораторные на локальном production-сервере, не полевые Core Web Vitals. Условия, HTTP/cache и исходные значения сохраняются; успешные прошлые проверки не выдаются за текущие.
- Генерация — встроенный image_gen, новые файлы без перезаписи исходников, полный набор промптов и происхождение в отчёте.

## Task 1. Воспроизводимый исходный замер

**Файлы:** scripts/measure-demo-performance.mjs, package.json, отчёт.
1. Chromium, 390×844, DPR 2, CPU ×4, сеть 200 KiB/s вниз, 100 KiB/s вверх, RTT 100 ms; новый контекст и отключённый browser cache.
2. Шесть главных плюс витрина. До измерения прогреть серверные ресурсы отдельно. Снимать FCP/LCP, оконный CLS, transfer по типам, ошибки и выбранные изображения.
3. Сохранить baseline JSON до правок. Трафик измерять CDP loadingFinished; LCP после загрузки и стабилизации, без пользовательского ввода.
**Приёмка:** семь результатов, никаких реальных заявок, статус 200, объяснение всех ошибок; метрики не подменять баллом Lighthouse.

## Task 2. Шрифты и адаптивные изображения

**Файлы:** fonts.css и новые WOFF2 рядом с TTF; scripts/optimize-demo-fonts.py + requirements; PrototypeLanding.tsx, EstimateLanding.tsx, DemoPages.tsx, app/page.tsx.
1. Сжать локальные лицензированные шрифты в WOFF2 без удаления кириллицы; исходники и OFL оставить. Python-зависимости только в игнорируемой папке инструмента.
2. Использовать штатный next/image с корректными sizes, размерами и loading для hero/карточек. Прочитать локальную документацию Next 16. Не добавлять клиентский image loader и runtime-пакеты.
3. Повторить тот же лабораторный профиль после production build. Цель: минимум 25% сокращения font transfer; отсутствие новых ошибок/переполнения; при ухудшении картинки/тайминга объяснить и исправить.
**Проверки:** lint/typecheck/build, проверка кириллицы и сети в браузере, замеры до/после. Не добавлять формальные тесты, повторяющие CSS.

## Task 3. Два дома Stay и доступная галерея

**Файлы:** src/features/prototypes/media.ts, OfferGallery.tsx, PrototypeLanding.tsx, DemoPages.tsx, styles.css, новые public/demo-assets/prototypes/stay/*, tests/e2e/stay-gallery.spec.ts.
1. Старый A-frame — экстерьер pine-house. Сгенерировать интерьер A-frame и пару экстерьер/интерьер горизонтального forest-house; явно маркировать визуальные концепты.
2. Типизированный медиареестр связывает только известные serviceId со своей серией; каталог, главная и страница дома используют нужный экстерьер.
3. Галерея: ручной выбор, диалог, предыдущий/следующий кадр, стрелки клавиатуры, Escape и возврат фокуса; нет autoplay. Размеры не скачут, миниатюры lazy, reduced motion.
4. Путь к заявке сохраняет выбранный дом. Новые фото не являются свидетельством реального объекта.
**Красный → зелёный:** сценарии различимости двух домов, выбора кадра, клавиатуры/фокуса, мобильного переполнения, отказа изображения и правильного serviceId. Chromium + WebKit.
