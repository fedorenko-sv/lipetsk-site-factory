# Фабрика: два рабочих ядра и шесть прототипов — план реализации

Дата: 18.11.2026. Основа: исходный 01_ROADMAP, версия 04.11.2026; modifiedTime повторно проверено через Drive и не изменилось. Новое поручение владельца: двигаться по остальным направлениям, спроектировать карту и начать реализацию. Рабочая ветка codex/six-prototypes от 0e6b887; отдельная папка portfolio.

**Цель текущего выпуска:** открыть из одной витрины все шесть оболочек; у пяти работает заявка Core A, у шестой — расчёт окон и заявка Core B. Техническое основание общее. Существующий многостраничный OBLIK сохраняется как подробный Auto-пример.

**Архитектура:** модульный монолит Next.js/TypeScript/PostgreSQL. Профиль оболочки задаёт композицию и содержание, SiteConfig — разрешённые услуги/ресурсы. Core A сохраняет контракт /api/leads. Core B получает отдельный контракт /api/estimates, чистую формулу и собственный сценарий, который использует существующие хранилище, идемпотентность, лимиты и outbox. Core C/RFQ — следующий подтверждаемый заказом этап, не фиктивно готовая функция.

**Навыки:** writing-plans, site-architecture и software-architecture. Выполнение в этой сессии; глобальные и проектные инструкции о делегировании сохраняются. Системную архитектуру не заменяем шесть разными приложениями.

## Исходная матрица

| Оболочка | До этой итерации | Следующий проверяемый результат |
| --- | --- | --- |
| A1 Technical Auto | Booking + полноценный OBLIK | Понятный вход в Auto и сохранённый подробный детейлинг. |
| A2 Editorial Beauty | Два сценария услуг в общей форме | Собственная журнальная главная, услуги/мастера и запись. |
| A3 Medical Trust | Нет | Спокойная информационная оболочка, демо-специалисты, запись без медицинских сведений. |
| A4 Friendly Sports/Kids | Нет | Программы/возраст, демо-тренеры, запрос на пробное занятие без обещания мест. |
| A5 Nature Stay | Нет | Дома и демонстрационные ориентиры, запрос на обсуждение поездки. Дата формы — время связи, не бронь ночей. |
| B1 Estimate/Construction | Нет | Параметры окна → объяснимый расчёт → заявка; сервер пересчитывает и сохраняет цену. |

## Итерации продукта

1. **Эта итерация — ширина и второе ядро.** Шесть самостоятельных визуальных направлений, общая витрина, работающие демо-сценарии Core A/B и независимая приёмка.
2. **Глубина по обратной связи.** Развёрнутые страницы Beauty; Medical/спорт/проживание расширяются подтверждёнными сведениями. Формулы мебели и клининга подключаются к Core B после окон. Набор страниц выбирается под реальные задачи, а не автоматически по 14 на каждую нишу.
3. **Клиентские модули.** Подтверждённые документы/контакты/материалы, выбранные каналы, реальное расписание и ёмкость, периоды/ночи/сезонность — отдельные функции с собственными контрактами.
4. **Core C/RFQ по заказу.** Каталог позиций, состав запроса, файлы спецификаций и менеджер. Не имитируем остатки, 1С и закупочный процесс.

## Критерии готовности и границы

Готовый прототип означает собственную визуальную подачу и рабочий синтетический сценарий, а не действующий бизнес. Тестовые контакты, noindex и demo-only сохраняются. Клиентские часы, лицензии, фотографии, отзывы и тарифы требуют фактов. Реальные уведомления, платежи, ночи/сезонность и групповая ёмкость в этом пакете не заявляются.
