Дата: 18.11.2026. Общая витрина открывает нужное направление. Каждое демо имеет собственные главную, разделы, меню, карточки предложений и отдельный сценарий заявки.

Это локальные адреса на компьютере владельца. Публичные домены и развёртывания в этой разработке не создаются. Для удалённого показа нужен отдельно опубликованный демонстрационный стенд.

## Как показывать

1. Открыть прямую главную выбранного демо.
2. Изучить подачу и каталог. Логотип, меню и подвал ведут внутри выбранного сайта.
3. Открыть конкретное предложение и перейти в заявку. Услуга, совместимый специалист или тип конструкции передаются в форму.
4. Использовать только +70000000000 и синтетическое имя. Согласиться с условиями демо.
5. Получить квитанцию. Сервер сохраняет заявку, затем recording создаёт проверочное свидетельство.

Для Stay день/время относятся к обратной связи. Для Sports место в группе не закрепляется. Для Medical не вводят симптомы, диагнозы или документы. Для Calculator стоимость предварительная, сервер пересчитывает её независимо от браузера.

## Запуск

Из папки репозитория:

~~~powershell
npm ci
npm run db:test:up
npm run build
npm run preview:portfolio
~~~

Оставить последний процесс работающим. Порт по умолчанию — 3035, PostgreSQL в compose — 55543. Другой локальный порт задаётся через PORTFOLIO_PREVIEW_PORT.

Проверка уже запущенного стенда:

~~~powershell
npm run verify:demo-routes
npm run test:portfolio:system
~~~

Первая команда обходит все страницы и проверяет HTTP, H1 и noindex. Вторая проходит шесть главных на трёх ширинах и реальные заявки до PostgreSQL/outbox/recording. Она удаляет только созданные ею синтетические лиды.

Общий самостоятельный system-контур:

~~~powershell
npm run test:system
~~~

Он запускает собственный сервер и проходит отдельные страницы предложений, выбранный контекст, квитанцию, запись в БД, повтор и recording. Внешние сообщения не отправляются.

## Отдельные публикации

Общая кодовая база не мешает показать каждое демо отдельно. Для одного стенда используются шесть прямых URL. Для шести развёртываний выбираются собственные домены/origin и ALLOWED_SITE_KEYS, отдельные env/БД и назначения. Корневой маршрут каждого развёртывания настраивается на нужный сайт при подготовке публикации.

Ни домены, ни реальные каналы администратора, ни коммерческие документы в текущем коде не считаются подключёнными. Recording подтверждает работу доставки внутри тестового контура. Канал конкретного заказчика выбирается отдельно.

## Что дальше улучшать

Основные страницы и маршруты уже существуют. Следующая клиентская итерация наполняет выбранное демо настоящими материалами и уточняет глубину: большой каталог, фотографии работ/объектов, сведения команды, согласованные условия и тарифы. Групповая ёмкость, календарь ночей и RFQ — отдельные продуктовые сценарии, а не обещания текущих форм.

## Новое в показе Stay и проверка загрузки

Каталог /demo/stay/houses показывает два разных архитектурных образа. На /demo/stay/houses/pine-house и /demo/stay/houses/forest-house доступны серии «снаружи/внутри», просмотр по клику, стрелки и Escape. Изображения — визуальные концепты; выбранный дом остаётся выбранным при переходе в заявку.

Шрифты и адаптивные изображения оптимизированы по лабораторным замерам. Метод, числа до/после, ограничения и команды: [отчёт](reports/presentation-polish.md). Измерения запускаются через npm run measure:demo-performance при работающем preview.

## Выбранный сайт как отдельный процесс

Пакет profiles позволяет открыть нужное демо на своём локальном origin с отдельной test-БД. Команда npm run preview:demo -- beauty запускает MIRA на 3042; остальные профили и правила описаны в [инструкции раздельного запуска](17-isolated-demo-profiles.md). Список адресов означает запуск соответствующего процесса; общая фабрика остаётся на 3035.
