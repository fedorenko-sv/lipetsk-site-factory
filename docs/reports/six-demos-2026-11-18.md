## Архитектура и поведение

Booking A использует прежний контракт POST /api/leads. Переданные через URL service/resource проверяются по конкретному SiteConfig. Неизвестный, чужой или неоднозначный контекст возвращает 404. Совместимые начальные значения попадают в форму и затем в БД.

Calculator B использует отдельный POST /api/estimates, строгую JSON Schema и чистую формулу в целых копейках. Цена не принимается из браузера: сервер пересчитывает её по параметрам и сохраняет версию формулы, допущения, строки суммы и параметры. Существующий LeadStore обеспечивает общие лимиты, конкурентную идемпотентность и атомарную запись lead/outbox. Worker сохраняет один recording receipt.

Статические статьи и каталоги отделены от динамических booking/calculator. Серверные назначения уведомлений остаются приватными. Пять Booking-подач используют общее состояние и транспорт; копий бизнес-логики для отдельных отраслей нет.

Пять новых изображений созданы для концептов, оптимизированы локально и описаны в public/demo-assets/prototypes/manifest.json. Это не фотографии реальных компаний или выполненных работ.

## Исправления, выявленные при контроле

1. Отдельные формы сначала попали в статическую ветку разделов и возвращали DYNAMIC_SERVER_USAGE в production. Они выделены в явные динамические маршруты. Повторный production-обход всех 69 адресов и реальные сквозные сценарии проходят.
2. Возврат фокуса после Escape в WebKit перенесён на завершённое закрытие native dialog. Меню, Escape и собственные переходы проверяются для всех шести сайтов.
3. Browser и system получили раздельные каталоги артефактов. Параллельные прогоны больше не удаляют трассы друг друга.
4. Проверка короткой анимации OBLIK удерживает настоящую native animation на паузе перед переключением reduced motion. Проверяется отмена анимации, а не случайное окончание её 440 мс.
5. UI не показывает квитанцию по HTML/битому ответу. Ошибки 422 параметров возвращают к их редактированию; неизменённая попытка после сетевого сбоя сохраняет ключ, исправленная получает новый.

## Зависимости и ограничения

Next.js и eslint-config-next обновлены с 16.4.3 до 16.4.6 после проверки предупреждения сборки. Затронутые диапазоны и исправления описаны в [первом advisory Next.js](https://github.com/vercel/next.js/security/advisories/GHSA-mfr8-8qww-v76h) и [втором advisory](https://github.com/vercel/next.js/security/advisories/GHSA-vc7v-qv4w-wrv8). npm audit --omit=dev после обновления: 0 уязвимостей.

Полный npm audit отдельно сообщает 15 записей dev-toolchain: 9 high и 6 moderate, в основном цепочки glob-пакетов. Их исправление требует совместимого обновления инструментов разработки. Это не нулевой полный audit; принудительный downgrade eslint-config-next не применялся. Результат npm audit нельзя трактовать как полную проверку безопасности приложения.

Статус выпуска — локальные demo-only версии для показа. Публичные домены и развёртывания не создавались. Нет реальных Telegram/email/CRM, оплаты, подтверждённых визитов, групповой ёмкости или ночей. Core C/RFQ не реализован. Реальные документы, команда, фотографии и коммерческие тарифы требуют материалов заказчика.

Метрики реального опубликованного сайта и Lighthouse в этой сессии не снимались. Готовность к live-запуску этим отчётом не утверждается.
