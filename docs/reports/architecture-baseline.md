Ветки: main, codex/frontend-pr3, codex/backend-pr3. Три отдельных checkout относительно папки задачи:

- outputs/lipetsk-site-factory — архитектор;
- work/lipetsk-site-factory/frontend — разработчик 1;
- work/lipetsk-site-factory/backend — разработчик 2.

В checkout разработчиков зависимости ещё не устанавливались: каждый начинает с npm ci. Разработчики в этом архитектурном этапе не запускались; подготовлены задания и общий Git-базис.

## GitHub и CI

[Первый Quality](https://github.com/fedorenko-sv/lipetsk-site-factory/actions/runs/41861662655) на e260bd4: шаги npm ci и npm run verify:architecture вернули success. На момент последнего чтения агрегатный статус run ещё был in_progress; завершение всего CI этим отчётом не утверждается.

Workflow настроен на push/PR в main, чтобы не дублировать запуск для двух одинаковых веток. При реализации продукта в quality нужно добавить реальные UI/backend/integration тесты.

Merge-метод — squash; автоматическое удаление постоянных веток выключено. Настройка защиты private main получила HTTP 403: GitHub требует другой тариф. Защита **не включена**; правило «main сливает архитектор» действует организационно.
