# OBLIK — кинематографичный лендинг детейлинг-ателье

Дата: 6 ноября 2026. Ветка: `codex/detailing-cinematic`. Основа: интеграционный PR-3 с сервером BR1–BR6 и frontend FR-исправлениями. Реализация выполнена архитектором по прямому поручению владельца «делай сам» в отдельном worktree.

## Что построено

Новый самостоятельный маршрут `/demo/detailing`: херо с автомобилем, описание подхода, выбор четырёх зон автомобиля, шесть услуг с демонстрационными ценами, крупные планы деталей, процесс работы, FAQ, запись и демо-политика. На общей витрине `/` появилась ссылка на OBLIK. Auto и Beauty сохранены.

Херо — бесшовный 12-секундный MP4 с медленным приближением и смещением камеры, подготовленный из специально сгенерированного кадра. Это движение по фотографии, а не натурная съёмка, генеративная анимация автомобиля или 3D-рендер в браузере. У автомобиля не меняется геометрия; двери не открываются.

Пользователь выбирает капот/переднюю часть, кузов, диски или салон через подписи либо точки на изображении. Выбор меняет программы и цены. Переключатель общего/крупного плана показывает соответствующее изображение с плавным приближением. Выбранная услуга передаётся в существующий мастер записи. Первый шаг здесь выполняет сам лендинг; следующие два — пожелание по времени и контакт/согласие/квитанция.

Запись использует настоящий `/api/leads`, существующие контракты, серверную цену, PostgreSQL и outbox. В локальном просмотре подключён только recording-адаптер: он создаёт тестовое свидетельство получения, не отправляет сообщения администратору. Канал реального заказчика остаётся настраиваемым.

## Как посмотреть и запустить повторно

Локальный адрес: `http://127.0.0.1:3032/demo/detailing`. Он доступен на компьютере владельца, пока работает процесс просмотра. С телефона этот loopback-адрес не откроется.

Из корня этой ветки, Node 22 и Docker Desktop:

```powershell
npm ci
npm run db:test:up
npm run build
npm run preview:detailing
```

При уже запущенной Docker-БД повторно поднимать контейнер не требуется. Скрипт просмотра привязан к `127.0.0.1:3032`, использует отдельную `lsf_test_detailing_preview` на тестовом PostgreSQL `127.0.0.1:55543`, создаёт её при отсутствии и применяет миграции в test-mode. Он не очищает другие базы. Секреты генерируются в памяти; live отключён; назначения всех трёх демо — recording. Повторный запуск при занятом порте останавливается с объяснением. Завершение запущенного в терминале скрипта — Ctrl+C.

Для формы: синтетический номер `+70000000000`, имя пустое либо вымышленное. Время — пожелание. Предварительные цены придуманы для демо и требуют замены перед работой с заказчиком.

После запуска просмотра повторяемая сквозная проверка: `npm run test:detailing:system`. Нужен установленный Playwright Chromium (`npx playwright install chromium`). Тест проходит страницу без подмены HTTP, выбирает уход за дисками, отправляет синтетическую заявку и сверяет квитанцию с lead/outbox/recording в отдельной тестовой БД. Результат и снимок квитанции сохраняются в игнорируемый `work/detailing/`. Такой запуск добавляет одну синтетическую заявку и подчиняется обычным ограничениям частоты; он не очищает другие записи.

## Визуальная идея и материалы

Входной материал — предоставленная владельцем запись MotionSites, 1920×1080, 10 секунд. Изучались композиция, масштаб автомобиля, тёмный фон, точки выбора деталей и движение камеры. Кадры чужих сайтов в страницу не переносились.

Направление: отражение студийного света как подпись на графитовом кузове. Непрерывный тёмный фон, светлый автомобиль, тёплый акцент, крупная кириллическая антиква. Типографика: локальные Manrope и Cormorant Garamond, лицензии OFL лежат рядом с файлами шрифтов. Никаких запросов в Google Fonts при посещении страницы.

Использован `design-taste-frontend`, выбран `dark-room`, seed `1075802814`. Предложенные генератором plum/pink и Imbue сознательно заменены на графит/шампань и Cormorant: цвет поддерживает свет на автомобиле, шрифт содержит кириллицу. Маски и градиенты служат растворению границы кадра и читаемости текста, как просил владелец.

Краткий арт-бриф:

1. Аудитория: владелец автомобиля, выбирающий защиту и деликатный уход.
2. Главная задача: понять программу и оставить пожелание по времени.
3. Тон: спокойный, внимательный, без искусственных гарантий и срочности.
4. Основной образ: графитовое купе в тёмной студии, блик по силуэту.
5. Живая часть: видео херо и выбор зоны с крупным планом.
6. Содержание: херо → подход → подбор → услуги → процесс → FAQ → заявка.
7. Материалы: четыре специально сгенерированных растра, два локальных шрифта, локальное видео.
8. Ограничения: демо, без реальных контактов, отзывов, логотипов производителей и внешних отправок.

Изображения созданы встроенным imagegen. Исходный размер каждого — 1672×941. Файлы `*-4k.jpg` экспортированы в 3840×2160 с Lanczos: это увеличенные версии, **не нативная генерация 4K**. В браузере используются более лёгкие WebP; крупные JPEG не загружаются на страницу.

Смысл использованных промптов:

| Материал | Задание генератору |
| --- | --- |
| Hero | Фотореалистичное немаркированное графитовое спортивное купе; передние три четверти, нос влево; автомобиль в нижней правой части; чёрная студия и много пустоты сверху; тонкий тёплый софтбокс по кузову; без текста и логотипов. |
| Paint | Макро графитового капота с водяными каплями; видимая фактура лака, тёплое линейное отражение, глубокие тени, без текста. |
| Wheel | Крупный план многоспицевого металлического диска и крыла графитового купе; тёмная студия, точный свет на металле, без эмблем. |
| Interior | Крупный план тёмного кожаного сиденья, шва и центральной консоли; тёплый мягкий свет, малая глубина резкости, без брендинга. |

Это описания промптов по смыслу; не экспорт служебного ответа генератора. Исходные PNG оставлены в каталоге генерации Codex; веб-версии и видео включены в Git. Пользовательские JPEG 4K находятся в `outputs/detailing-media/` рабочей папки задачи.

Видео: H.264, yuv420p, без звука, faststart, 30 кадров/с. Desktop 1920×1080 — 1 443 394 байта; mobile 1280×720 — 588 166 байт. При `prefers-reduced-motion` или `saveData` источник видео не назначается. Есть постер, пауза, остановка вне экрана/при скрытой вкладке и безопасный fallback при отклонённом `play()`.

## Почему именно так и как перейти к 3D

| Подход | Что даёт | Что нужно |
| --- | --- | --- |
| Видео + постер, сделано | Предсказуемый красивый херо, компактные файлы, быстрое открытие | Клип либо исходный кадр и монтаж движения камеры |
| Набор кадров, сделано частично | Смена общего/крупного плана, интерактивные зоны и услуги | Согласованная серия изображений; вращение возможно только по заранее подготовленным ракурсам |
| Настоящий GLB-viewer, следующий отдельный блок | Свободный поворот, точное попадание в детали, двери/капот/багажник | Подготовленная 3D-модель с раздельными деталями, корректными осями вращения, материалами и анимациями; лицензия на web-использование |

Обычная монолитная модель машины не обеспечивает открывание дверей сама по себе. Для полной версии нужен asset-контракт: `hood`, `trunk`, `door_left`, `door_right`, группы кузова/стёкол/дисков/салона; pivot в реальных петлях; клипы открытия и закрытия, либо управляемые узлы; состояния камеры front/body/wheels/interior. Нужны совместимые материалы, сжатые текстуры, мобильный уровень детализации и постер при недоступном WebGL.

Предлагаемая реализация следующего слоя: лениво загружаемый viewer после действия «Исследовать автомобиль», отдельный компонент вместо фотографического stage, стабильные `zoneId` и `serviceId` сохраняются. Камеру интерполировать между заданными позициями; дверь и выбранная зона должны быть связаны с программой ухода. На мобильном оставить прокрутку страницы одним пальцем, явно объяснить жест вращения и добавить «Вернуть вид». Уменьшение движения и fallback обязательны. До получения модели нельзя обещать достоверную геометрию из четырёх фотографий.

Основания по первичным источникам: [`<video>`: autoplay, muted, playsinline и poster](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video); [управление камерой model-viewer](https://modelviewer.dev/examples/stagingandcameras/); [анимации и смешивание клипов model-viewer](https://modelviewer.dev/examples/animation/); [GLTFLoader Three.js](https://threejs.org/docs/pages/GLTFLoader.html). Эти источники описывают возможности инструментов; разбиение автомобильной модели выше — наше проектное решение.

| `npm run test:ui` | 24 / 24 passed |
| `npm run build` | exit 0; статические маршруты Detailing и privacy, существующие Auto/Beauty и API собраны |
| Общий `test:e2e` | 70 / 72 passed в первом полном прогоне; два таймаута WebKit Windows — старт видео и старый FE11 |
| `npx playwright test --grep 'DT0[1-6]\|FE11' --reporter=list` | после проверки причин 14 / 14 passed, без skip: все шесть новых сценариев и FE11 в Chromium и WebKit |
| `npm run test:detailing:system` | PASS: реальный браузер → HTTP 201 → lead/outbox в PostgreSQL → `sent` → ровно одно recording-свидетельство; leadId совпадает с UI |

Новый DT01 требует фактического увеличения `currentTime` у видео, а не только наличия атрибутов. Диагностика показала, что WebKit до назначения `src` и начала воспроизведения тратит несколько секунд на загрузку/гидратацию. Для старта выделено до 20 секунд без фиксированного sleep; воспроизведение, пауза, возобновление и остановка вне экрана проверяются по реальному состоянию элемента. Старый FE11 повторно прошёл с прежними утверждениями и прежним 45-секундным лимитом. Единого заключительного прогона «72/72 одной командой» здесь не заявляем; логи полного и целевого запусков сохранены отдельно.

DT02 проверяет отсутствие загрузки MP4 при уменьшении движения. DT03 проверяет точки/зоны, крупный план, цену, предвыбор услуги и возврат фокуса. DT04 сверяет выбранную программу с HTTP-телом и квитанцией. DT05 проверяет отсутствие ложного успеха при 503 и сохранение idempotency key при повторе. DT06 проверяет телефонный viewport, изображения, FAQ и privacy. В browser-тестах транспорт подменяется только на границе теста; отдельный system-прогон выше не использует HTTP-подмен.

Снимки получены на 1440, 768 и 390 px: горизонтального переполнения и ошибок JavaScript не обнаружено. Шрифты и изображения загружаются локально. Реальный Safari/iPhone не проверялся: Playwright WebKit на Windows не равен Safari на устройстве; [документация Playwright об отличиях платформ](https://playwright.dev/docs/browsers).

После визуального аудита увеличен основной текст до 16 px, убраны декоративные номера, подписи над заголовками и тонкие разделители. Сохранены тёплый цвет отражения и курсив во второй строке заголовков как единый приём. Итоговый повтор визуальных проверок и снимки сохраняются вместе со свидетельствами.

После этой правки повторены DT01/DT03/DT06 в двух движках: **6 / 6 passed**. Финальная сборка — exit 0. Последнее уточнение сетки вводного блока и удаление повторной инструкции проверены визуальным инспектором и повторным настоящим system-сценарием: **0 FAIL на 1440/768/390 и system PASS**. Во всех трёх размерах нет overflow и ошибок JavaScript.

Пять предупреждений визуального инспектора разобраны вручную: курсив сохраняет единую двухстрочную интонацию заголовков; тёплый акцент повторяет свет на кузове; подсчёт размеров включает крупный логотип и пиктограммы; назначение страницы прямо написано под H1 («Детейлинг-ателье в Липецке»); FAQ сознательно сохраняет две колонки на планшете. Это зафиксированные решения, не выключенные проверки.

Итоговый локальный просмотр вынесен на **3032**; адреса предыдущих стендов относятся к прежним версиям. Публичный live-стенд и отправка настоящих уведомлений в этой работе не запускались.

Свидетельства: [финальный визуальный отчёт](detailing-evidence/taste/report.json), [desktop](detailing-evidence/taste/desktop-fold.jpg), [mobile](detailing-evidence/taste/mobile-fold.jpg), [14 browser-проверок](detailing-evidence/e2e-final.log.txt), [6 проверок после полировки](detailing-evidence/e2e-visual-final.log.txt), [реальный system](detailing-evidence/real-flow-result.json), [квитанция](detailing-evidence/real-receipt.png). Полный прогон с двумя первоначальными таймаутами также сохранён, без подмены результата.

В ходе проверки исправлены две причины нестабильности: позиционный transform точки выбора конфликтовал с общим нажатием кнопки; старый FU23 зависел от даты календаря и не заполнял обязательный параметр услуги. В FU23 фиксируется время и задаётся валидная услуга; продуктовая валидация не ослаблялась. Генерируемые отчёты Playwright исключены из ESLint, исходники тестов остаются под проверкой.
