# PR-3 Авто — план реализации

> Для исполнителей: выполнять своё ТЗ по контрольным точкам; вести чекбоксы в PR. Дополнительных агентов не запускать. Архитектор принимает результат и интегрирует ветки.

**Цель:** к 10.11.2026 получить проверенный путь заявки для Auto и материалы первого показа.

**Архитектура:** один Next.js-проект; публичный конфиг и тема отдельно от Booking UI; серверный сценарий сохраняет lead/outbox в PostgreSQL и уведомляет администратора независимо.

**Стек:** Next.js App Router, TypeScript, Tailwind, Node.js 22 LTS; pg/PostgreSQL и тестовые инструменты добавляются общим коммитом архитектора.

Сроки — рабочий план из источников, не факт выполненной разработки и не обещание коммерческого результата. Все даты — Europe/Moscow.

## G1 — скелет и первые мобильные кадры, 4–5 ноября

Агент 1: заменить стартовую страницу маршрутами /demo/auto и политикой демо, загрузить Auto-конфиг, реализовать OfferStep и статические состояния остальных шагов. Получить 3 скриншота 390px с явной отметкой «прототип».

Агент 2: подготовить миграции, валидатор и тесты нового запроса/ошибок, контейнер тестовой БД. Согласовать с архитектором серверные зависимости и конфиг подключения.

Архитектор: один общий коммит зависимостей (pg, серверная валидация, Vitest, Playwright, генератор типов); обновить обе ветки из main. Если зависимости ещё не согласованы, разработчики продолжают независимые UI/SQL/тестовые спецификации.

**Выход G1:** интерфейс можно показать как прототип; серверная модель проверяется отдельно; схема не расходится между агентами.

## G5 — решение о выпуске, 10 ноября

Архитектор выдаёт одно из решений:

- **release-ready:** все P0 выполнены, есть проверенное долговременное сохранение и полученная администратором согласованная тестовая заявка, реальные тексты/контакты утверждены.

Публикация рабочего стенда выполняется после отдельного поручения. Портфолио/обращения к лидам выполняет владелец или отдельно уполномоченный исполнитель; эта задача не запускает рассылку.
