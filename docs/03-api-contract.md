# Контракт заявки 1.0.0

Машиночитаемый источник синтаксиса — [OpenAPI](../contracts/openapi.json). Примеры — [booking](../examples/http/booking-request.json), [успех](../examples/http/created-response.json), [ошибка](../examples/http/validation-response.json). Изменяет архитектор до того, как оба агента начинают зависимую реализацию.

## POST /api/leads

Content-Type: application/json. Обязателен Idempotency-Key: UUID. Same-origin; Origin должен совпадать с явным allowlist среды. Cookie-сессии и логин для формы не нужны. Запрос — не больше 16 KiB.

| Поле | Правило |
| --- | --- |
| siteKey | Разрешённый конфиг; в live должен совпадать с привязкой текущего развёртывания |
| configVersion | Версия контента/прайса; при устаревании 409 CONFIG_CHANGED |
| kind | Только booking в 1.0.0 |
| serviceId | Активная услуга из серверного конфига |
| serviceOptions | Только объявленные ключи/значения для этой услуги; пример wheel-size=R16 |
| resourceId | Необязателен; если задан, существует и поддерживает услугу |
| preferred | Необязателен на уровне схемы; обязателен, если preferenceRequired=true; дата/время/Europe/Moscow |
| customer.phone | Принимаем формат с пробелами/скобками; 8xxxxxxxxxx преобразуется в +7xxxxxxxxxx; +7xxxxxxxxxx — 11 цифр всего; другие значения 422 |
| customer.name | Необязателен; trim, 1–80 символов; не вставлять как HTML |
| consent | accepted строго true; version совпадает с конфигом; consentAt устанавливает сервер |
| attribution | Только utm_source/utm_medium/utm_campaign, не более 80 символов каждое; до разрешения сбора сервер отбрасывает |
| antiBot.website | Пустая строка; непустое значение даёт 422 REQUEST_REJECTED |

Схема запрещает неизвестные поля. В live дополнительно отклонять номер +70000000000, зарезервированный в этом проекте как синтетический тестовый ввод. Это правило проекта, не утверждение о нумерации операторов. Demo допускает только этот фиксированный ввод.

Сервер получает услугу/цену/назначение из своего конфига. Имена политик, адрес назначения, цену, consentAt и createdAt присылать нельзя.

## Ответы

| HTTP | Code / смысл | Действие интерфейса |
| --- | --- | --- |
| 201 | received, leadId, replayed=false — lead и outbox сохранены | Результат внутри третьего шага |
| 200 | Тот же leadId, replayed=true — совпадающий повтор | Тот же результат; не новая заявка |
| 400 | INVALID_JSON / IDEMPOTENCY_REQUIRED | Общая ошибка; данные остаются |
| 403 | ORIGIN_NOT_ALLOWED | Общая ошибка; не повторять автоматически |
| 404 | SITE_NOT_FOUND | Сайт недоступен; без раскрытия конфигураций |
| 409 | IDEMPOTENCY_CONFLICT / CONFIG_CHANGED / CONSENT_CHANGED | Конфликт ключа или запрос обновить сводку/согласие |
| 413 | PAYLOAD_TOO_LARGE | Общая ошибка |
| 415 | UNSUPPORTED_MEDIA_TYPE | Общая ошибка |
| 422 | VALIDATION_FAILED / REQUEST_REJECTED | Ошибки рядом с полями и общая сводка |
| 429 | RATE_LIMITED + Retry-After в секундах | Повтор после указанного срока, поля сохранены |
| 500 | INTERNAL_ERROR | Общая ошибка, requestId для диагностики |
| 503 | STORAGE_UNAVAILABLE / DEMO_NOT_READY / LIVE_NOT_READY | Нет успеха; можно повторить после восстановления |

Каждый ответ — Cache-Control: no-store. Ошибка содержит error.code, error.message, error.requestId и при необходимости fieldErrors. Телефон, SQL, env и сообщение провайдера в ответ не попадают.

Успех означает получение заявки, не подтверждение времени и не успешную доставку уведомления. Текст: «Заявка получена. Администратор свяжется с вами и подтвердит время». Не обещать срок ответа без утверждённого SLA.

## Идемпотентность и конкурентные запросы

1. Клиент создаёт UUID перед первой отправкой и сохраняет при timeout/неизвестном исходе. После явной 422 или изменения данных создаёт новый ключ.
2. Сервер нормализует данные и вычисляет HMAC канонического payload; состав включает siteKey, configVersion, услугу, параметры, предпочтение, контакт, версию согласия и разрешённую attribution. Игнорировать antiBot после проверки.
3. UNIQUE(site_key,idempotency_key) обеспечивает единственный lead. Lead и outbox вставляются одной транзакцией.
4. Конкурирующий такой же запрос ждёт завершения транзакции, читает сохранённую запись и отвечает 200 с тем же leadId. Не реализовывать через проверку SELECT перед INSERT без unique.
5. Тот же ключ и иной payload → 409, не перезапись заявки. После успешного ответа поля можно очистить; новая заявка получает новый ключ.
6. Существующий успешный повтор доступен до срока удаления лида и проверяется до расходования лимита новых попыток. Проверки Origin, размера, синтаксиса и antiBot выполняются всегда.
7. Устаревание конфига не должно ломать получение уже сохранённого идентичного повтора. Сначала разрешить siteKey и проверить повтор, затем текущие бизнес-правила для новой заявки.

Строго одинаковый новый запрос с другим ключом не считается повтором на уровне протокола. Защита кнопки предотвращает случайный дубль интерфейса; rate limit ограничивает злоупотребления.

## Ресурсы и время

Ресурс входит в список разрешённых для услуги. Смена услуги в UI сбрасывает несовместимый ресурс и параметры. Предпочтение валидируется по локальному календарю сайта, включая невозможные даты, прошлое время, часы работы и горизонт. Отсутствие предпочтения при обязательном поле → fieldErrors.preferred.

Сервер не проверяет свободную ёмкость и не создаёт бронирование. Одно и то же пожелание может быть у нескольких лидов.

## Приватность и эксплуатация

Нет публичного GET /api/leads, поиска по телефону и административного кабинета. Экспорт для владельца — локальный CLI с отдельными правами, запись файла по явно указанному пути вне Git; повтор/удаление и доступ к БД — только оператору.

Уведомление в Telegram включается после решения владельца и настройки разрешённого chat_id. До согласования передачи контакта наружу в тестах использовать синтетику. Даже успешная тестовая отправка не разрешает автоматически принимать реальные данные.
