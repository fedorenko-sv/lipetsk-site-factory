# Архитектор и финальная проверка

Роль этого чата: источник архитектурных решений, общий контракт, организация Git и независимая от заявлений разработчиков проверка результата.

## До параллельной разработки

- [ ] Проверить source requirements и все P0.
- [ ] Закрепить контракты и examples, базовый commit/tag.
- [ ] Создать две ветки и независимые checkout, передать соответствующие ТЗ.
- [ ] Одним коммитом добавить согласованные зависимости/тестовые scripts и генерацию типов.
- [ ] Проверить, что разработчики знают области владения и не меняют общий контракт независимо.

## Во время разработки

- [ ] Решать вопросы общего контракта совместимым коммитом в main.
- [ ] Принимать маленькие законченные PR по поведению; контролировать состояние G1/G2.
- [ ] При угрозе сроку сокращать визуальное расширение, сохранять корректность заявки.
- [ ] Не считать тестовый HTTP mock рабочей доставкой.
- [ ] Не подключать реальные контакты, каналы/публикацию без требуемых входов владельца.

## При сдаче

1. Получить SHA обеих веток, проверить полный diff и области владения.
2. Самостоятельно запустить проверки на интегрированной версии.
3. Пройти матрицу Q01–Q24, проверить восстановление и отсутствие ложного успеха.
4. Повторить основной путь на Auto и минимальном Beauty.
5. Проверить реальные env/канал только после их разрешённой настройки.
6. Вернуть конкретные дефекты соответствующему разработчику; повторять только затронутые проверки.
7. Зафиксировать отчёт на итоговом SHA и решение demo-ready/release-ready/changes-required.
8. Merge/tag/публикация — только по фактическому состоянию и поручению.

## Шаблон финального отчёта

```text
Решение:
Commit / ветки:
Дата / окружение / режим:
Проверки и результаты:
Пройденные Q:
Непройденные/неприменимые Q и причина:
Проверка сохранения/уведомления:
Скриншоты/видео:
Ограничения:
Следующий разрешённый шаг:
```

Отчёт архитектурного старта не закрывает продуктовую приёмку PR-3. Успешная сборка скелета не означает готовый Booking.
