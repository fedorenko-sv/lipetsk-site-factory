# Lipetsk Site Factory

Переиспользуемые сайты для малого бизнеса Липецка: понятный прайс → заявка без звонка → ручное подтверждение администратором.

**Текущий этап: архитектурный старт.** Репозиторий содержит стартовый Next.js-проект, контракт API, две демо-конфигурации, план и ТЗ. Три шага PR-3, сохранение лидов, уведомления и публичный релиз ещё предстоит реализовать.

## Решение и команда

Один проект, общее ядро Booking/Lead, контент и темы через конфигурацию. Первый выпуск — **PR-3 Авто до 10.11.2026**, затем PR-4 Beauty на том же ядре. Calculator — следующий этап после обратной связи; B2B RFQ — под заказ.

Канал получения заявок выбирается отдельно для каждого заказчика: Telegram, почта или существующая CRM через подходящий адаптер. Настройка серверная; интерфейс и API заявки одинаковы. В первый релиз конкретного клиента подключается один согласованный канал, остальные добавляются по спросу.

| Роль | Ответственность |
| --- | --- |
| Архитектор, этот чат | Контракты, решения по архитектуре, интеграция, Git, финальная проверка и решение о готовности |
| Разработчик 1 | Интерфейс, три шага, тема Auto, клиент заявки, мобильная доступность и скриншоты |
| Разработчик 2 | API, проверка данных, PostgreSQL, идемпотентность, сохранение и уведомление администратору |

## Начало работы

Node.js 22 LTS, npm; версии зависимостей закреплены в package-lock.json. Не перегенерировать проект через create-next-app поверх этого репозитория.

```powershell
npm ci
npm run verify:architecture
npm run dev
```

Начальная страница сообщает, что демо готовится. Форма и маршрут /api/leads появятся в ветках разработчиков; текущая сборка не является рабочим приёмом заявок.

Проверка архитектурного старта проверяет документы, схемы/примеры, lint, типы и сборку. Это не проверка будущей бизнес-логики.

Передать каждому ссылку на репозиторий и соответствующее ТЗ целиком. Разработчик 1 работает в codex/frontend-pr3, разработчик 2 — в codex/backend-pr3. У каждого отдельная папка или clone. main ведёт архитектор; общий контракт меняется через согласованное решение и отдельный коммит архитектора.

В текущей итерации выполнять только короткое задание ниже, чтобы сохранить ограниченный объём работы и проверяемый результат.
